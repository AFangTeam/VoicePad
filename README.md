# VoicePad

**专为铁三角 Audio-Technica ATV-SG1 的 `+EXT` 双麦录音而做，也适用于其他双声道视频。**
ATV-SG1 在这个模式下把机顶枪麦录在**左声道**，外接领夹麦录在**右声道**。
枪麦能保留更自然的空间和细节，领夹麦在距离变化时更稳定；拍摄时两条都留着，
剪辑时再决定各占多少。这正是 VoicePad 要解决的事。
[English README](README.en.md) · [ATV-SG1 官方说明](https://www.audio-technica.co.jp/product/ATV-SG1)

VoicePad 是一个在本机运行的网页调音板，灵感来自二维调色盘：**左右**混合两条声道，
**上下**调人声音色，几秒钟就能找到这一条素材的「甜点值」。它还支持自动对轨、
逐素材参数、批量导出；**视频流直接复制，只重新制作音轨**。无需 npm 依赖，
只用 Node 标准库和 ffmpeg/ffprobe。它是独立的创作者工具，与铁三角没有隶属关系。

> ATV-SG1 的 `SAFE` 模式与 `+EXT` 不同：它把同一支麦克风的较低电平备份录在右声道。
> VoicePad 可以选择或混合两边，但在 `+EXT` 模式下两边才分别是枪麦和外接麦。

## 项目缘起

作者从日本带回 ATV-SG1 后，最喜欢的是它让「用领夹麦，还是用枪麦」变成了
「同时录两支麦」。领夹麦适合作为距离稳定的保障音轨；枪麦不用给每个出镜者佩戴，
把镜头转过去也能收音，并能保留更自然的声音细节。不同场景下两者各有优势，
所以这个工具把选择留到剪辑时：先对轨，再拖动面板找一个适合当前镜头的配比和音色。

## 快速开始（Windows / macOS）

1. 安装 [Node.js 22+](https://nodejs.org/en/download) 和 [ffmpeg/ffprobe](https://ffmpeg.org/download.html)。
   Windows 用户可从 FFmpeg 下载页进入 “Windows EXE Files”，解压后把其中的 `bin`
   文件夹加入系统 `PATH`；macOS 可用 `brew install ffmpeg`。在新终端里分别运行
   `node --version`、`ffmpeg -version`、`ffprobe -version`，确认三个命令都能找到。
2. 在本项目目录打开 PowerShell 或终端，运行 `node server.js`。
3. 在浏览器打开 <http://localhost:5178>，拖入视频，或粘贴素材文件夹路径。

服务只监听 `127.0.0.1`；音视频在本机处理，不上传到云端。拖放模式会将文件送到**本机**
服务端的临时目录，以供对轨和导出；文件夹路径模式直接读取本地文件，无需复制整段素材。

Windows 网页版尚未经过实机测试；如果遇到兼容问题，欢迎提交 issue。

## macOS 独立应用

在 macOS 上运行 `./macos/build-app.sh` 后，项目根目录会生成可双击的 `VoicePad.app`。
它有独立窗口和图标，应用包内包含当前机器的 Node、ffmpeg、ffprobe 以及网页代码；
关闭窗口时会停止本地服务。

应用包是本机生成的产物，不纳入 Git。修改源码后重新运行构建脚本。
构建需要 macOS 的 Swift 命令行工具，以及本机可用的 Node、ffmpeg、ffprobe。
这个应用包仅供本机使用；若要分发给其他 Mac，还需处理架构兼容、代码签名和公证。

## 调音面板

一个面板管两个维度：**左右**决定两条输入声道各占多少（左端=纯左、右端=纯右、
中间=等量混合），**上下**调这一路的音色 —— 往上是电容麦的玻璃质感，
往下是动圈麦近讲效应那种低沉磁性。面板上方一条总音量。
**画面直通不重编码，只替换音轨**，支持批量。

## 两种载入方式

| | 怎么用 | 导出到哪 | 要不要拷贝 |
|---|---|---|---|
| **拖放**（默认）| 从文件管理器拖进窗口，或按「选择文件…」| macOS `~/Movies/VoicePad/`；Windows 用户目录下的 `Videos/VoicePad/` | 对轨或导出时传到本机服务一次 |
| **文件夹路径** | 头部「用文件夹路径」展开后粘路径 | 源文件旁边 `_voicepad` | 不拷贝 |

为什么拖放要上传：浏览器**不给**拖进来的文件的绝对路径（`File.path` 是 Electron
才有的），服务端读不到，只能把字节传过去。预览不受影响 —— 那一路走 blob URL，
瞬时可播、根本不经服务端。

素材本来就在磁盘上某个目录、又是大批量时，用文件夹路径那条更省事：几个 GB 不用白搬一遍。

两条路径都**不覆盖原文件**，重名会自动加 `_1` / `_2`。

## 产出是单声道

左右不是声像平衡，是 **blend 权重** —— 产出只有一路声音。典型场景是相机双轨：
一轨机头麦、一轨小蜜蜂，或者一轨接了 mic 另一轨是底噪。用左右在两轨之间找那个
最干净的配比，而不是让它们分别待在左右耳里。

用**等功率**（cos/sin）曲线而不是线性 crossfade：线性权重在中点各 0.5，
两轨若不相关（两个独立声源），功率相加只有 0.707，中点会明显变轻。
等功率下两路权重平方和恒为 1，**不相关**的两路在各位置响度更稳定；
两路若高度相关，中点仍可能更响，因此建议试听后决定配比。

### 双声道监听

按钮开启后可以听原始双轨长什么样。此时 pad 整体压暗、光点不发光 ——
**拖得动但不生效**，明确告诉你现在是在监听不是在调。
这只是个监听工具：**导出永远是调好的那一路单声道**，和这个按钮无关。

## 甜点值 复制 / 粘贴

找到好听的配比后按 `Ctrl/⌘C`，在列表里勾选其他素材，按 `Ctrl/⌘V` 应用过去，
已应用的素材会打上「已调」标记。

参数是**逐素材**存的：批量粘贴后再单独微调某一条，导出时那条用它自己的值，
不会被全局参数抹掉。

## 单声道素材

相机常见的单声道素材会在入口处自动升成双声道（两边等量），预览和导出一致。
这曾是一个真 bug：`ChannelSplitter` 对单声道输入的右声道输出是**静音**，
于是单声道素材预览只有左耳有声、往右拽平衡近乎全静音 —— 而导出没这个问题，
属于最不能容忍的"预览≠导出"。面板两侧的左右电平表就是为这类问题装的：
声道对不对，看一眼就知道，不用戴着耳机猜。

## 最要紧的一件事：预览 == 导出

面板上听到的和导出的必须是同一个声音。这类偏差用耳朵很难当场发现，
等发现时素材已经交付了。

所以滤波器只有**一个真相来源** —— `public/dsp.js`：

| 通路 | 怎么用同一套系数 |
|---|---|
| 实时预览 | Web Audio `BiquadFilterNode` |
| 导出 | ffmpeg `biquad` 滤镜，喂**显式系数** |

不用 ffmpeg 自己的 `equalizer` / `bass` / `treble`，因为它们的参数化方式和
Web Audio 不完全一样（尤其 shelf 的斜率），用了就等于两边各算各的。

### 实测（不是推断）

三条通路逐点比对，全部一致：

```
Web Audio  vs  dsp.js 解析计算      最大偏差 0.0000 dB
ffmpeg 实测 vs  dsp.js 解析计算      最大偏差 0.0009 dB
```

ffmpeg 那一侧是真跑的：喂一个冲激进去，把脉冲响应 DFT 出来，
和解析频响逐点比。

### 途中抓到的两个坑

**Web Audio 的 shelf 没有斜率参数。** 规范里固定 `S=1`，而且 `Q` 对 shelf 无效。
我一开始用 `S=0.8`，实测 80Hz 处两边差 **3.8 dB** —— 这就是"预览和导出是两个声音"。

**Web Audio 对 highpass 的 `Q` 是分贝制**（`alpha = sin(w0)/(2·10^(Q/20))`），
而 RBJ 原始公式里 Q 是无量纲的。不换算低频同样会差好几个 dB。

## EQ 选点的依据

不是随便挑的频率。人声频段地图：

| 频段 | 是什么 |
|---|---|
| 60–80 Hz | 隆隆声、手持噪声 —— 该切 |
| 100–160 Hz | 胸腔共鸣、厚度。动圈麦近讲效应主要抬这里 |
| 200–350 Hz | 浑浊、箱声 —— 抬这里会糊 |
| 2–4 kHz | 清晰度、临场感（过头就是"冲"）|
| 5–8 kHz | 齿音 —— 抬这里会刺 |
| 10–14 kHz | 空气感、玻璃质感 |

**往下拽（低沉磁性 · 罗德 VideoMic 那种）**

- 180 Hz 低架 +7 —— 近讲效应本体
- 330 Hz 峰值 −3.2 —— **防糊的关键**。只抬低频不切这里会闷成一团。
  这一刀必须够窄：实测放 280 Hz / Q 1.0 时裙边一路啃到 150 Hz，把厚度吃掉一半
- 3.2 kHz 峰值 −3.5 —— 收齿音边缘，听感是"顺滑、暗"

**往上拽（玻璃质感 · 电容麦那种）**

- 8 kHz 高架 +6.5 —— 空气感
- 2.2 kHz 峰值 +2.5 —— 清晰度，**刻意压在 3–5 kHz 那个"冲"区以下**
- 5.5 kHz 峰值 −2.8（窄 Q）—— **防刺的关键**，专压 s/sh
- 250 Hz 峰值 −2 —— 去浑浊

两个方向都常开 70 Hz 高通。

**峰值补偿**：整条链的最大增益会被反向补回去。所以拖动时响度基本不变，
你判断的是音色而不是"变大声了所以好听"，顺带保证不削波。

## 导出

- `-c:v copy`：视频流一个字节不动。实测导出前后视频流 MD5 完全相同
- 音频 AAC 256k —— 已经过一遍 EQ，低码率会把刚调好的高频毁掉
- 输出到源文件旁边的 `<原名>_voicepad.<后缀>`，**不覆盖原文件**
- 导出产物不会再出现在素材列表里，避免二次 EQ
